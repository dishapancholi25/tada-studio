# Ticket #45444 - API Rate Limiting Too Aggressive
**Date Resolved:** 2024-09-30
**Category:** technical_support
**Urgency:** 3
**Customer:** DataSync Solutions
**Plan:** Enterprise

## Issue Description
Customer's integration failing due to 429 (Too Many Requests) errors. Claims they're well within their plan limits.

## Root Cause
Rate limiter was counting failed requests toward limit, causing legitimate retry attempts to be blocked.

## Resolution Steps
1. Increased customer's rate limit temporarily from 1000 to 2000 requests/minute
2. Fixed rate limiter to only count successful requests
3. Implemented separate retry bucket with higher limits
4. Added rate limit headers to all responses for transparency

## Customer Communication
"We've identified and fixed the rate limiting issue. Failed requests no longer count toward your limit, and retry attempts now have a separate, higher limit. Your current limits:
- Standard requests: 1000/minute
- Retry requests: 500/minute
- Burst allowance: 2000 requests

Rate limit info is now included in all API response headers."

## Technical Implementation
- X-RateLimit-Limit header added
- X-RateLimit-Remaining header added
- X-RateLimit-Reset header added
